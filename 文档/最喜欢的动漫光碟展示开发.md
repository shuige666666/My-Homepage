## 交互与验收

1. 卡片打开：以卡片序号为目标，从第一盘有方向感地滑动到目标盘；快速连续操作不会出现错误落位。
2. 画廊浏览：滚轮、左右方向键、底部序号和左右按钮逐盘切换；空白区域及邻盘拖动或触摸横向滑动切换；点击相邻盘将其选中。
3. 盘面反馈：鼠标位置驱动当前盘和左右邻盘轻微立体摆动；按住中间盘拖动时可连续转到背面，松开后缓动回弹，不切换作品；仅当前盘出现手绘圈，盘面反光随真实朝向变化；空格键可翻转当前光碟；减少动态效果偏好下使用直接落位。
4. 导航：单击当前光碟或按回车，在新标签打开它的 Bangumi 链接；拖动结束不会误触跳转。关闭按钮和 Esc 退出，焦点返回原卡片。
5. 视觉与适配：专辑图圆裁不出现方角；十张图均能显示，移动端可浏览且无横向页面溢出；关闭画廊后原主页滚动位置不变。

## 实施说明

默认盘面使用 Three.js 实体几何和物理材质；WebGL 不可用时回退到原有 CSS 3D 透视盘。悬停圈用不规则 SVG 路径逐段描画。当前盘和左右可见邻盘都能随指针轻摆，只有当前盘显示线条。滑动位置逐帧计算，连续操作从当前视觉位置重新起步，减少跳帧。

参考页复核后，运动模型改为同一条左下至右上的弧线：当前盘落在画面中央，上一盘和上上盘依次位于左下、逐渐缩小和转正；下一盘位于右上、放大并增加斜角。盘位变化时位置、尺寸和倾角同步插值。左侧光碟保持不透明，不再以淡出代替空间运动。使用原生 `dialog` 管理焦点和 Esc 关闭，切换时不会修改主页首屏「深度画廊」。

第二次对照发现，先前的 `skewX` 会把专辑图拉成不自然的平行四边形，源站更接近整张圆盘绕竖轴转动后的透视椭圆。现在盘位只组合 Z 轴朝向与 Y 轴透视；普通悬停仅有克制的角度变化，按住盘面拖动才扩大转角。松手后角度和队列位移分别按弹簧阻尼继续落位；画面上的反光局限于盘面，不使用周围的渐变光晕。手绘圈只响应当前选中的光碟，避免鼠标经过后方盘面时抢走视觉焦点。

先前对左拖闪动的判断不完整。旋转后的命中轮廓变窄只是一个因素；打开时盘列仍在移动、当前作品序号改变时，旧代码还会直接把非当前盘的倾角写回零，硬性角度上限也使极限姿态显得突兀。现在拖动持续绑定最初按下的盘，序号改变不会清零它的姿态；转角从按下时的实际姿态出发，允许盘面连续转到背面。空白处拖动只改变队列位置，不附加盘面转角。松手或系统取消后，角度通过阻尼回到悬停或默认姿态。

持续拖动还需要避免事件与绘制两侧相互影响：手绘圈不再由旋转后的 `:hover` 命中区域驱动。现用指针射线与当前三维姿态的盘面求交，只有落在实际可见圆盘内才进入旋转；倾斜光盘旁的留白拖动整列光盘，重叠处优先命中镜头前方的盘。超过拖拽阈值后锁定最初按下的盘，避免转到侧立时丢失事件。桌面预览中，从首张盘左侧留白向左拖能切到第二张；按住盘面内部拖动只旋转当前盘。早期 CSS 盘曾在拖动时隐藏背面以压住闪烁，但这与参考站不同；现在实体盘的正反面与倒角边缘都参与渲染。短按不会捕获指针，保留单击光碟的原有操作。

原站再次实测：中央盘左拖先侧立，继续拖动会短暂露出背面，松开后回到正面；左右邻盘同样会响应鼠标，只有中间盘绘制手绘圈。之前关于“极限只到侧立”的记录不准确。本站早期 CSS 版本已有按空格翻面的背面 DOM，但银色外缘一度遮住背面；后续层级已修正，并保留为 WebGL 不可用时的回退版本。

## 物理材质迭代（2026-10-02）

参考站当前加载的 `main.qdXy8l6N.js` 确认使用 Three.js。它的盘面不是简单的平面图片：封面、背面、倒角边缘和盘心分别采用物理材质，配有暗环境中的灯带反射、主光、补光、轮廓光、长条面光源，以及粗糙度/法线贴图。本站复用已有的 Three.js 依赖，按需在弹窗内创建独立 WebGL 画布；十张原图映射到有中心孔的圆环几何，背面使用暗色刻纹与克制的薄膜干涉，盘边和盘心分别使用金属及半透明材质。程序生成的纹理只影响高光和细微法线，不在原图上直接叠灰色污渍。

中间盘拖动改为从按下姿态累计转角，约每像素四分之一度，最多转半圈；按住时提高跟随速度，松开后用原有阻尼弹簧回正。邻盘和空白区域拖动按视口宽度控制队列距离，触摸比鼠标更克制。对照原站翻面画面后，把过暗的背面调成深绿色，并提高刻纹在斜光下的可见度。浏览器里复查了快速左拖露背与回弹、400px 空白拖动切换一张、邻盘拖动及点击、空格翻面和 390px 手机视口。画布不接受指针事件，透明按钮继续负责点击和键盘访问；首次贴图解码期间以及 WebGL 初始化失败时仍能看到 CSS 盘面。

画廊直接使用 `public/images/album/raw` 中的十张 JPG 原图，不压缩或替换用户素材，浏览器运行时按盘面形状裁切；原图合计 12.04 MiB。此前尝试过 1400px WebP 衍生图，用户最终选择恢复原图。首张原图提前加载，收藏区接近视口时再预载开场附近的另外两张；打开较后的作品时先请求途经封面，再成对解码，避免高清图同时解码造成顿挫。无对应本地文件的新条目会回退到 Bangumi 封面。

## 性能与关闭控件迭代（2026-10-02）

参考站的脚本会限制透射通道分辨率并按运行情况调整画布尺寸。本站上一版使用全分辨率透射，画廊画布在当前桌面预览中达到 2548 × 1171，同时每帧读取 CSS 布局，并在关闭后留着第二个 WebGL 上下文。这些都是卡顿的可能来源，因此把透射通道降到半分辨率、限制画布像素密度与大屏像素总量，并在连续慢帧时逐档降画质；同时缓存舞台尺寸、只更新可见盘面的 CSS 变量，悬停时只处理当前及上一张盘，关闭时释放画布和纹理。物理封面纹理也改为盘面进入视野附近才上传；贴图尚未就绪的盘继续显示 CSS 回退盘，避免短暂出现白色空盘。当前桌面预览的初始画廊画布为 2123 × 975，像素数下降约 31%。首屏深度画廊离开视口后不再为鼠标移动读取布局，交接动画稳定后暂停逐帧循环；交接途中也不再绘制离屏 WebGL，滚动回来则重新唤醒。

右上角关闭控件改为无文字的深色圆形按钮，保留可访问名称、键盘焦点轮廓及轻微悬停反馈。浏览器复查了桌面长距离拖动、邻盘切换、关闭后再次打开，以及 390px 视口下的视觉和关闭操作。页面观感需要继续由实际设备确认，本文不把画布像素下降等同于确定的帧率提升。

后续发现封面看起来发糊并非 JPG 原图被处理：慢帧降档后，画廊在桌面预览里曾以 1168 × 536 的画布铺满约 1699 × 781 的区域，停稳后没有恢复。现在运动时继续用动态分辨率保流畅，盘面停稳即按设备像素密度重绘一帧；粗糙度与法线贴图只作用于反光，不对封面颜色纹理做模糊滤镜。

首次打开较后作品时发现开场时序竞争：目标路线的 JPG 已解码，盘列就开始滑动，但首张 WebGL 盘的贴图可能尚未完成绘制，CSS 备用盘会在运动途中突然交给实体盘，看起来像首张盘乱转或跳动。现在先等首张实体盘完成贴图与首帧绘制，再启动开场位移；贴图接管也改为先绘制再隐藏 CSS 盘。WebGL 不可用时仍直接使用 CSS 盘继续导航。

继续在全新标签页逐帧复现，确认上面的贴图时序修复还不够：点击第三部后，真实盘列状态曾从位置 0 瞬间跳到 9，下一帧又回到 0，随后才正常移动到 2；期间只发生一次导航，没有多余的滚轮事件。根因是启动动画时用 `performance.now()` 记时，而首次 WebGL 编译可能让下一次 `requestAnimationFrame` 回调携带早于该记时点的帧时间戳。旧逻辑只限制时间步上限，负时间步进入弹簧积分后造成极端过冲。现在首帧使用零时间步，此后仅使用相邻 rAF 帧时间戳，并把时间差限制在非负区间，避免首次打开时从第一张闪到末张再弹回。
