# Preview 页面开发交接

整理日期：2026-11-13。项目目录：`E:\Study\My Homepage`。

## 1. 目标与当前阶段

用户正在改进动漫主页的信息展示部分，希望降低罗列感，获得 PC 网页应有的空间感、层次与动效。目前已实现独立 `/preview` 页面，接下来的会话应在这份实现上继续完善。

**最终目标是在预览完善并通过回归后，用新版信息展示部分替换正式首页对应内容。不要把任务永久停留在独立示例页，也不要现在就用整个 preview 文件直接覆盖首页。原开幕画廊需要保留，并与新版信息页完成衔接。**

这份文件是开发交接，不表示当前视觉已经最终定稿。本次整理没有迁移正式首页，没有创建新会话，也没有提交或部署。

## 2. 已明确的设计要求

桌面端采用一个模块一整屏的节奏，目前的信息密度可以。最近看过和评分与短评需要分开，观看时间轴也要真正占据完整视口。手机端优先保证阅读和操作，不强行把长评论压缩成一屏。

开幕的六幕进入画廊，以及最喜欢动漫的光碟设计，是用户精心模仿、调整过的部分。继续沿用现有实现；不要擅自更换光碟材质、尺寸、轨迹、倾角或重新设计开场。预览已经允许将同一套光碟舞台整屏嵌入信息页。

收藏必须能浏览十部作品，默认从第三张「悠哉日常大王」开始，让左侧有邻盘。循环轮播可以留到后续，当前不是必做项。全部短评二级页面沿用原版纸页弹层，用户认可其设计。

**不要自行增加修辞性标题、宣传语或作品描述。** 用户明确拒绝过「偏爱，值得被珍藏。」「有些故事，看过以后就一直留在心里。」「最近，又看了什么。」「把日子，慢慢存档。」等文案。只使用模块名称、用户已有资料、真实记录与必要操作提示。

动效要继续完善，但不应破坏整屏节奏、文字阅读、正常页面滚动或原有交互。现有动效是第一轮实现，后续依据实际视觉和用户反馈细化。

## 3. 当前实现

项目使用 Astro、TypeScript、原生 CSS、Three.js，没有 React 客户端层。数据来自构建时读取的 `src/data/bangumi.json`，不要为了演示改写真实记录。时间轴使用收藏记录更新时间，不应描述为准确的看完日期。

当前 `/preview` 依次展示：个人资料 → 我最喜欢的动漫 → 最近看过 → 评分与短评 → 观看时间轴。

## 4. 开始下一轮开发

先查看 `git status`、本文件、当前页面和 `ARCHITECTURE.md`，再按用户的新反馈继续修改。保留现有工作，不执行清理工作区或整体回退，不假定所有修改都来自上一轮。

源码使用 UTF-8。PowerShell 读取中文文件时显式指定 `Get-Content -Encoding UTF8 -LiteralPath ...`。新增或重写方法补充简洁中文注释，说明作用和关键处理原因。

先围绕章节衔接、运动幅度与节奏、画面比例、鼠标和触摸反馈继续打磨。保持现有信息密度与模块边界，不要为制造变化重新堆内容。循环光碟、增加依赖或全面重构都不应成为默认前置工作。

已有资料位于 `文档/信息展示页设计分析-2026-11-12/`：`设计分析与改版建议.md` 保存早期参考分析，`preview-v3/修订说明.md` 和同目录截图记录最近一轮实现及验证。更早的建议如与用户后续要求冲突，以本文件和用户最新指令为准。

参考网站汇总在 `设计参考/网页参考.md`。本任务主要参考 Andres Hunger、ATELIER NORTH、get-daffed、VirtuaReal 和 Codrops Rotating On-Scroll Animations。需要继续研究实际动效时重新打开页面观察，不把参考站当成必须逐项照搬的清单。

## 5. 本地运行与验证记录

上轮交付地址为 `http://127.0.0.1:3001/preview`，它是构建后的静态预览。新会话先确认服务是否仍在运行，**不要把 3001 当成会自动热更新的开发服务**。修改后需要重新构建；日常迭代使用开发模式。

```powershell

npm run dev
npm run build
node ./node_modules/astro/astro.js preview --host 127.0.0.1 --port 3001
```

最后一条是启动构建预览服务，长时间运行属正常。启动前检查已有服务，避免重复占用端口。上轮 3000 开发服务出现过 Vite `504 Outdated Optimize Dep`，造成动态导入的光碟渲染模块失败；3001 构建版已验证 WebGL 正常。遇到类似情况先核实服务与依赖缓存，不能把 CSS 备用光碟当成真实材质效果验收，也不要因此改坏渲染代码。

上轮验证过 1440×900、2560×1280 和 390×844；桌面各内容章节与视口等高，手机无页面横向溢出。十条海报浏览、原版短评翻页、作品 ID 定位、时间轴到短评的跳转及关闭后焦点恢复均已检查。原主页光碟仍能按选中作品进入，构建版的原主页与预览都确认了 `has-webgl`。

上轮 `npm run build` 成功，Astro 检查 27 个文件，无错误、警告或提示；Vite 仍有原有的 Three.js 分包超过 500 kB 提示。减少动态效果分支已实现并读代码检查，但未通过浏览器工具模拟系统设置。这些是历史验证结果，新的修改后需做对应回归。

## 6. 完善后的正式首页替换

### 替换范围与结构

正式入口仍为 `/`，保留 `DepthGallery`。替换的是开幕之后的旧信息展示区域，目标体验为「原开幕画廊 → 新版信息页的五个章节」。不要通过把 `/` 重定向到独立 `/preview` 来丢掉开场。

建议先将新版信息主体提取为可复用的 Astro 组件，例如 `AnimeInfoPage.astro`，让 `/preview` 与正式首页在过渡阶段使用同一份内容。组件名可以按项目实际情况调整，关键是避免复制成两套随后分叉的页面。不要嵌套两份 `BaseLayout`、HTML 文档或重复的弹层。

### 已核实的接入边界

1. **画廊交接与锚点。** `depth-gallery.ts` 通过 `.page-shell` 找到信息页；`DepthGallery.astro` 的跳过链接指向 `#top`。保留这两个接口，或统一修改所有调用方。建议保留外层 `#top.page-shell`，用明确的新版修饰类覆盖旧容器的内边距和宽度限制。
2. **画廊交接样式。** `depth-gallery.css` 的 `.depth-intro ~ .page-shell` 使用负一屏上边距、`--homepage-reveal` 透明度和子节点位移，并通过 `depth-gallery-active` / `depth-gallery-home` 切换交互状态。不能只换正文而忽略这些规则；也不要为了接入而重做原六幕效果。
3. **滚动吸附。** 目前 `preview.css` 在 `html:has(.pv-page)` 上启用纵向 proximity 吸附。正式首页同时有连续滚动的开幕画廊，需要限定吸附的生效阶段，检查边界切换，避免开场被吸到信息页或滚动突然跳跃。
4. **动效初始化。** `index.astro` 当前加载 `home-motion.ts`，`BaseLayout.astro` 加载 `home-motion.css`。接入后检查旧规则是否仍有用途，避免两套观察器、hover 或变换同时作用。预览的首屏入场也应与画廊交接配合，不能在画廊遮盖时提前播放完。
5. **共用组件实例。** 光碟与短评脚本目前使用页面级查询，按单实例设计。替换旧信息区域时移除重复实例，确保 `review-dialog` 和其他 ID 唯一，作品入口只绑定一次；不能同时放着隐藏的整套旧页面。
6. **正式入口清理。** 移除「原版主页」对自身的链接和页面标题中的「预览」，检查页内导航、回到顶部、Bangumi 外链与描述。`/preview` 可以暂时保留为对照路由，但不应再是查看新版的唯一入口。

### 迁移验收

在根路径实际走通开幕、进入信息页、向上返回开幕、跳过画廊、直接打开 `/#top` 和章节锚点。检查首屏没有空白、重复内容或未恢复的点击锁定，章节吸附不干扰画廊。

再确认十张光碟默认第三张、浏览与翻面、WebGL 材质、十条最近记录、完整短评、月份切换和展开列表。覆盖桌面、宽屏、窄屏、键盘与减少动态效果，检查连续滚动性能和离屏 WebGL 资源释放。时间轴展开允许自然增加高度，不要为维持固定一屏裁掉作品列表。

最后完成构建、页面回归、更新架构与说明，再清理确认不再被引用的旧代码。正式首页替换是后续开发的目标；对外部署按届时任务范围执行，不能把本地完成当成已经发布。
